AI Chat receives non-secret settings from a ConfigMap and secret settings from a Kubernetes Secret.

## Application environment

| Variable                  | Required                 | Description                                          |
| ------------------------- | ------------------------ | ---------------------------------------------------- |
| `DATABASE_URL`            | Yes                      | PostgreSQL connection URL                            |
| `BETTER_AUTH_SECRET`      | Yes                      | Authentication secret with at least 32 characters    |
| `SETTINGS_ENCRYPTION_KEY` | Yes                      | Root encryption key with at least 32 characters      |
| `BASE_URL`                | Yes                      | Externally visible application origin                |
| `SETUP_CLAIM_TOKEN`       | For protected first boot | Operator claim token with at least 16 characters     |
| `ALLOW_PRIVATE_EGRESS`    | No                       | Set `true` to allow private and cluster destinations |
| `ALLOW_INSECURE_HTTP`     | No                       | Set `true` to permit HTTP provider and MCP endpoints |

<Warning>
  `ALLOW_PRIVATE_EGRESS` and `ALLOW_INSECURE_HTTP` weaken the outbound security
  boundary. Keep both false in normal production installations.
</Warning>

## Helm mapping

```yaml
config:
  baseUrl: https://chat.example.com
  allowPrivateEgress: false
  allowInsecureHttp: false
  setupClaimTokenRequired: true

secrets:
  existingSecret: ai-chat-secrets
  keys:
    databaseUrl: DATABASE_URL
    authSecret: BETTER_AUTH_SECRET
    encryptionKey: SETTINGS_ENCRYPTION_KEY
    setupClaimToken: SETUP_CLAIM_TOKEN
```

Change `secrets.keys` when an externally managed Secret uses different key names.

## Workload resources

```yaml
replicaCount: 1

resources:
  requests:
    cpu: 100m
    memory: 256Mi
  limits:
    memory: 1Gi
```

The application pods are stateless, but the current chart uses `Recreate` strategy so a serialized migration init container completes before the application starts.

## Network policy

```yaml
networkPolicy:
  enabled: true
  internetEgress: true
```

The policy allows application ingress on port 3000, DNS, bundled PostgreSQL on port 5432, and HTTPS egress when enabled. Adapt it for external database destinations, proxies, service meshes, or private provider endpoints.

## Local development

```bash
cp .env.example .env
docker compose up -d postgres
bun install
bun run db:migrate
bun run dev
```

Replace every example secret before starting. Local HTTP requires `ALLOW_INSECURE_HTTP=true` only when testing provider or MCP endpoints over HTTP; the application itself can run at `http://localhost:3000`.
